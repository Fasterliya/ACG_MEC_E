## 0. 结论摘要（先看这 8 条）

1. **母 mod 新版做了一次兵种体系重构**：新增 36 个科技组 `acgr_g01..g36`，并把「兵种组」从 `technology_group` 里独立出来，改用国家级 `unit_type = acgr_gXX` + `set_country_flag = acgr_unit_group_gXX` 标记。`technology_group` 一律退回原版组（western 29 国 / muslim 7 国）。
2. **我方 36 个幻想乡国家在母 mod 新版里已被全部接管**：36/36 都有 `unit_type` 与 `# BEGIN ACGR_UNIT_GROUPS` 段（g01 为主，g02 月兔系、g09 樱系）。
3. **我方 submod 是「整文件覆盖」型**：2222 个文件里有 **1319 个与母 mod 同名**（覆盖即替换）。母 mod 新版对这 1319 个文件的全部更新，在我方 submod 生效时**全部失效**。
4. **科技组冲突的实质**：我方 `common/technology.txt` 只有 20 组（含 `tech_gensokyan`），会**抹掉母 mod 的 36 个新组**；`common/technologies/mil.txt` 会**抹掉 981 条新 enable**（含 855 条 acgr 兵种解锁）。这两处是「一开游戏就坏」级别。
5. **`tech_gensokyan` 与 `western` 在科技数值上完全等价**（`start_level 3` / `start_cost_modifier 0`）。它唯一的作用是：① 作为我方 72 个 `gen_t*` 兵种的 `unit_type` 归属；② 作为 1870 个省 `discovered_by` 的视野锚点。**这是后面所有取舍的支点。**
6. **省份冲突已精确量化**（`03` 报告逐省核实）：1270 个「双方都覆盖」的省里，**1015 个只是多一行 `discovered_by = tech_gensokyan`**（合并 = 取母 mod 新版 + 加一行，零裁决），**255 个有实质差异**，其中高风险 239 省（D2 顶层标签 49 + D4 日期条目 205）。D2 全貌：`qng→qin` 22 省、`fra→jda` 13 省、文化 `ShiraiKuroko→supperability_magic_culture` 5 省、`hmc→lsw/shj` 5 省、`hts↔frr` 互换 3 省、`add_core` 1 省。**关键结论：没有一例「幻想乡势力被母 mod 抢走」** —— KTY/RES/YKR/SHI/HTS/FRR 的地盘母 mod 自带（母 mod 的 101 Genoa 本身就是 `owner = KTY` / `culture = Sanae` / `religion = Gensokyo_reg`），我方省份层的私有内容实际只有 `discovered_by` 一行 + 12 个 WS 独有省。
7. **合作伙伴（PT）做的是一整套「科技组体系迁移」**（不是简单覆盖）：他把母 mod 326 国的 `technology_group` 从原版组整体改成 `acgr_g01..g36`（36 组全覆盖：g09 40 国、g07 40 国、g01 36 国…），省份的 `discovered_by` 同步改成这 36 组（每省 10–30 条），72 个幻想乡兵种的 `unit_type` 统一改成 `acgr_g01`，`technology.txt` 换成母 mod 55 组（删 `tech_gensokyan`），`mil.txt` 合并成 1865 条。**这套方案自洽**（国家用的 36 组 = 省份写的 36 组，无死组），但代价有 4 条：① **科技成本被抹平**（acgr 组全部 `start_cost_modifier 0`，而原版 muslim 0.4 / chinese 0.6 / indian 0.5 / eastern 0.2 的惩罚消失，涉及 150+ 国的平衡）；② **幻想乡兵种一刀切**（72 个不同兵种全部挂 `acgr_g01`，月兔系/樱系/专属炮兵差异化全丢，7 国看不见自家兵种）；③ 省份 `discovered_by` 冗余 6–8 万行；④ 母 mod 每次改版图/加国家都要重跑这套迁移。
8. **推荐路线**：`technology.txt`（56 组）+ `mil.txt`（1864 条 enable）先做**两文件合并**（半天内可让游戏跑起来）；省份按「915 自动合并 + 355 人工裁决」两批处理；最后对国家层做一次体系取舍（保留我方幻想乡兵种 vs 并入母 mod acgr 兵种，见 §6 决策点）。

## 3. 三个核心冲突的最终判定

### 冲突 1：科技组视野（`discovered_by`）—— 你的理解对了一半

**机制事实**（`VANILLA4/history/provinces/1-Uppland.txt:15-18` 原版即 4 条；原版全库 `discovered_by` 取值统计显示取值集合 = 18 个原版 technology group **+ 国家 TAG**（KAZ/SPA/GOL…））：

- `discovered_by = X` 的匹配对象是**国家的 `technology_group`**（或国家 TAG 作为历史发现者），**不是 `unit_type`**。
- 因此：**母 mod 的 36 个 `acgr_gXX` 一个都不需要写 `discovered_by`** —— 因为没有任何国家的 `technology_group` 是 acgr 组（`MOD/history/countries` 全库 `technology_group = acgr_` 命中 **0**）。
- 我方 `tech_gensokyan` 是国家 `technology_group`，所以**它必须逐省写** —— 这就是 1870 条 `discovered_by = tech_gensokyan` 的由来，本身没有错。
- 母 mod 自己的省份文件里 `discovered_by = acgr_` 命中数 = **0**（`MOD` 全库核实），反过来证明它不需要。

**结论**：
- 若保留 `tech_gensokyan`（36 国仍用它作 `technology_group`）→ 1870 条必须保留，且**新增的省**（母 mod 新版有、我方没有的 1228 个省不需要管，因为我方没覆盖它们；只要保证我方覆盖的 1270 个省带上这一行）。
- 若放弃 `tech_gensokyan`（改用 western/muslim）→ 1870 条可全部删除，视野自动继承原版。
- `PT` 的做法（删 tech_gensokyan + 加 22 条 acgr 的 discovered_by）**两头都错**：我方 36 国将全图不可见，而新加的 22 条全库无任何国家受益。

## 4. 关键判据：`tech_gensokyan` 要不要留？

**科技数值等价性**（决定性）：

| 组 | `start_level` | `start_cost_modifier` | `nation_designer_*` |
|---|---|---|---|
| `western` | 3 | 0 | 有 |
| `tech_gensokyan`（`WS/common/technology.txt:213-229`） | 3 | 0 | 有（与 western 同构） |
| `acgr_g01..g36`（`MOD/common/technology.txt:214+`） | 3 | 0 | `always = no` |

→ **`tech_gensokyan` 在科技成本、起始等级上与 `western` 完全一致，不提供任何科技优势**。它存在的唯一实际意义是：
- ① 作为我方 72 个 `gen_t*` 兵种的 `unit_type` 归属；
- ② 作为 1870 个省 `discovered_by` 的视野锚点。

所以「留不留 tech_gensokyan」= 「**要不要保留我方 72 个幻想乡兵种 `gen_t*`**」。这是必须你拍板的唯一决策点（见 §6）。

**第二条硬证据（决定 `technology.txt` 必须合并，没有选择余地）**：

原版 14 个 `unit_type` 取值**全部落在 `common/technology.txt` 的组名集合内（0 例外）**——即「兵种组必须先注册成科技组，`unit_type` 才能被引擎识别」。由此推出：

- 我方 `WS/common/technology.txt`（20 组）覆盖母 mod（55 组）→ **36 个 `acgr_gXX` 注册被抹掉** → 母 mod 的 972 个兵种文件（`unit_type = acgr_gXX`）+ 280 国的 `unit_type = acgr_gXX` 全部指向**未注册的组**。
- 这是「一进游戏就出问题」级别，且与我方是否保留 `tech_gensokyan` 无关——**即使走方案 B，也必须让 technology.txt 保持母 mod 的 55 组**（方案 B 就是直接删掉我方这个文件、用母 mod 的）。
- 同理 `mil.txt`：我方版本 0 条 `enable = acgr_*`，而母 mod 有 855 条 → 母 mod 的 acgr 兵种在科技等级上**永不向任何国家解锁**。

**第三条（澄清一个常见误解）**：`acgr_gXX` 在母 mod 里**只是兵种组**，不是科技组。`MOD` 全库 `technology_group = acgr_` 命中 **0**（`unit_type = acgr_` 命中 280 国 / 972 兵种文件）。因此在母 mod 的原始设计里，**这 36 组根本不需要任何 `discovered_by`**（它们不是任何国家的科技组，视野凭 `technology_group = western/muslim` 命中原版 4 条）。

**第四条（方案空间的关键前提）**：`unit_type` 与 `technology_group` 是**两个正交的轴，可以并存**，不是二选一。

- `wiki 历史修改.html:331-333`：「`technology_group` 确定科技组和兵种组，默认是相同的；`unit_type` 当科技组和兵种组不同时，单独设定兵种组」
- 原版实证：`VANILLA4/history/countries/ABB - Dongola.txt:7-8` 同时写 `technology_group = east_african` + `unit_type = sub_saharan`（原版共 89 处 `unit_type`）
- 母 mod 的 `set_country_flag = acgr_unit_group_gNN` **没有任何消费者**（`acgr_use_gNN_effect` 全库 0 调用点），真正生效的只有 `history` 里的 `unit_type`；另有 `ACGR_unit_group_effects.txt:662-670` 的 `acgr_change_legacy_unit_type_effect`，在 `change_technology_group` 之后把兵种组重挂回去

→ 由此得到三种合法组合（对应 §6 的 A2 / A / B），选哪种只取决于你想让 36 国的**兵种**用我方 `gen_t*` 还是母 mod `acgr`。

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 覆盖导致母 mod 内容静默失效 | 任何 `WS` 与 `MOD` 同名文件 | 阶段 1–5 全部改成「以母 mod 为底本 + 追加我方块」，禁止「以我方为底本整份覆盖」 |
| 36 国开局崩 | `technology_group` 指向不存在的组 | 阶段 1 与阶段 3 **必须同批次提交**，不能只做一半 |
| 兵种不可用 | `mil.txt` 缺 `enable`，或 `unit_type` 指向不存在的组 | 阶段 2 后跑「悬空检查」脚本：`enable` 名 ↔ `common/units` 文件名双向对账 |
| 版图错乱 | 省份 owner 与 `history/countries` 的 `capital` 不一致 | 阶段 4 后跑交叉校验：每国 `capital` 省的 `owner` 必须 = 该国 TAG |
| **文化空引用** | 99/100/1931/4381/4382 的 `culture = ShiraiKuroko` 在 vanilla / `MOD` / `WS` 三处 `common/cultures` 均无定义（`MOD` 只有 `supperability_magic_culture`） | 合并时统一改成 `supperability_magic_culture`；并回 `common/cultures` 核一遍有无其他孤儿文化引用 |
| **省会名编码损坏** | `MOD` 的 681 / 2171 / 2172 `capital` 是坏编码乱码 | 合并时按原版或 `WS` 的可读名回填 |
| **同 TAG 双份文件** | `PT` 的 `SKR` / `TMY` / `NNM` 各有两份内容冲突的文件 | 二选一并删除另一份，否则由加载顺序随机决定 |
| **KGY 系被单向拉出幻想乡科技组**（既有风险，非本次引入） | `MOD/decisions/KGYdecision.txt:298-307` 对 KGY 及全部附庸执行 `change_technology_group = western`，而 `WS` 全库 0 处 `change_technology_group` → 无回程 | 在 `WS` 补一条反向效果（事件/决议/`on_action`）：`change_technology_group = tech_gensokyan`；或让 KGY 系直接采用母 mod 的 acgr 兵种体系（方案 B） |
| 后续母 mod 再更新又全崩 | 我方继续整份覆盖 | 长期方案：把「我方增量」写成独立文件（新建 `ZZ_*` 前缀文件 / 用 `scripted_effects` 注入），尽可能少覆盖母 mod 同名文件 |

回滚：每阶段一个 commit；`git checkout -- <file>` 单文件回滚；整体回滚 `git reset --hard 6447ea4`。
