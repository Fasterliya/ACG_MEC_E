# MSK 任务树布局范式库

> 用途：把已经验证过的任务树排布方式固化成**可复现的范式 + 数值指纹**。
> 以后要给用户提方案时，直接引用范式编号和指纹，用户按编号选，不用重新描述形状。

| 文件 | 作用 |

## 1. 硬规则（EU4 1.37.5 任务树几何）

写任何范式前先记住这四条，越界就是连线不画、树塌成一根竖柱。

| # | 规则 | 说明 |
|---|---|---|
| R1 | `slot` = **列**，取值 1–5 | 从左到右第几列 |
| R2 | `position` = **行**，从 1 起 | 从上往下数，最顶是 1 |
| R3 | 同列依赖：`Δ行 ≥ 1` | 父可以隔任意行在正上方 |
| R4 | 跨列依赖：`Δ行` **必须恰好 = 1** | 父必须在**上一行**；`Δ列` 不限（±1/±2/±3 甚至越过别的列都行） |
| R5 | 同行（`Δ行 = 0`）或反向（`Δ行 < 0`）一律非法 | 原版 1.37.5 里也几乎没有这种写法 |

推论（排布时最省心的三条）：

- **剖面开得越宽，跨列边就越只能落在相邻行** → 想画扇形，必须让每层错开正好一行。
- **列可以留空**（`slot` 不必连续填满），`position` 也可以跳号，但跳号会在视觉上留空洞。
- **同列可以叠很多层**（MSK 的征服列叠了 10 层），这是撑深度最廉价的办法。

## 2. 特征指纹（8 个数值描述一套布局）

给任何布局算出这 8 个数，就等于给了它一张身份证；提方案时只报指纹即可。

| 记号 | 含义 | 怎么算 |
|---|---|---|
| `R` | **根数** | 无 `required_missions` 的任务个数 |
| `D` | **深度** | 最大 `position` |
| `C` | **用列数** | 出现任务的 `slot` 种类数 |
| `P ▸` | **剖面** | 每行节点数，写成 `3-5-5-5-5-4-5-4-1` |
| `F` | **填充率** | 节点数 ÷ (`C` × `D`) |
| `X` | **跨列边占比** | 跨列依赖 ÷ 全部依赖 |
| `J` | **汇合点** | `required_missions` 里元素 ≥ 2 的任务数 |
| `K` | **收口** | 最深那一行（或最后两行）的节点数 |

辅助观感值：

- `W` **最宽行** = `max(P)`，决定横向是否"满"
- `B` **分叉点** = 子节点 ≥ 2 的任务数
- `Lmax` **最长链** = 最长连续依赖链长度（决定多久能看到反馈）

## 3. 范式 P1 · 漏斗收束（Funnel）★ 已落地

### 3.1 形状

```
行1    ●        ●        ●          3 根（左/中/右各一条线的起点）
行2    ●   ●    ●   ●    ●          5 列首次铺满
行3    ●   ●    ●   ●    ●
行4    ●   ●    ●   ●    ●          中段：每行最多 5 个
行5    ●   ●    ●   ●    ●
行6    ●        ●   ●    ●          逐层抽稀
行7    ●   ●    ●   ●    ●
行8    ●        ●   ●    ●
行9              ★                   三线汇入唯一终局
```

视觉读法：**上方 3 个入口 → 中间撑满 → 下方收成一个点**。与官方大明任务树（巩固地盘 / 大明的陨落 / 朝廷安泰 → 五列展开 → 统一中国）同构。

### 3.2 结构约定

| 项 | 约定 |
|---|---|
| 根 | 固定 3 个，落在**列 1 / 列 3 / 列 5**（`pos = 1`），天然对称 |
| 中段 | `pos = 2` 起每行尽量填满 5 列；填不满就抽掉最外侧的格子 |
| 主线 | 三条竖脊分别走列 1、列 3、列 5；列 2 / 列 4 放支线与横移节点 |
| 横移 | 需要换列时，子节点必须放在父节点的**下一行**（R4），这是唯一的硬约束 |
| 终局 | 最深一行放 1 个新任务，`required_missions` 同时挂三条线的尾节点（各距离 1 行，正好都是合法跨列边） |
| 深度 | 通常 `D = 8~10`；再深就建议拆成两套任务树 |

### 3.3 指纹（MSK 实例）

| 值 | 数值 |
|---|---|
| `R` | **3**（`1_1` / `3_1` / `5_1`） |
| `D` | **9** |
| `C` | **5** |
| `P ▸` | **3-5-5-5-5-4-5-4-1** |
| `F` | **82%**（37 / 45） |
| `X` | **22%**（8 条跨列 ÷ 37 条依赖） |
| `J` | **1**（终局 `3_9`，三父） |
| `K` | **1** |
| `W` | 5 |
| `B` | 5（`1_1` 分征服/低地，`3_1` 分商路/产业，`1_4` 分北欧/炮厂，`1_6` 分北欧/超电磁炮，`3_5` 分红线） |
| `Lmax` | 9（`3_1 → … → 3_9`） |

### 3.4 优点 / 代价

- **优点**：① 三个入口一眼能看出"三条线"；② 中段满铺，横向不留空洞；③ 底部收口给出明确长线目标；④ 支线可以随意挂在任一列而不破坏形状。
- **代价**：① 需要新建一个终局任务（含 title/desc/icon/trigger）；② 中段每行都要凑节点，任务总数少时会显得"硬凑"；③ 跨列边集中在相邻行，画面上斜线密集，需要靠颜色区分线路。

### 3.5 变体

| 变体 | 剖面 | 适用 |
|---|---|---|
| `P1-a` 标准漏斗 | `3-5-5-5-5-4-5-4-1` | 36–40 个任务，5 列 |
| `P1-b` 浅漏斗 | `3-5-5-5-3-1` | 20–26 个任务，快速收口 |
| `P1-c` 双腔漏斗 | `3-5-5-5-5-3-3-1` | 30 个任务，中段两组支线并排 |
| `P1-d` 不对称漏斗 | `2-4-5-5-4-3-1` | 只有两条主线时（去掉一个根，重心偏一侧） |

## 4. 范式 P2 · 三色纵带（Banded）

每条线占**连续列区**，颜色分区最干净。

| 项 | 约定 |
|---|---|
| 列分配 | 红 1 / 灰 2 / 绿 3-4 / 金 5（可按线数缩放） |
| 根 | 每段色区一个根，`pos` 一般都在 1 |
| 特点 | 跨列边极少，几乎全同列竖链，最不容易越界 |
| 指纹 | `R=3`、`D=10`、`C=5`、`P ▸ = 3-4-5-5-3-5-5-4-1-1`、`F=72%`、`X=17%`、`J=0`、`K=1`、`W=5`、`B=4`、`Lmax=10` |
| 代价 | 没有终局；深度靠单列硬叠，底部容易拖出长尾（`-1-1`） |

---

## 5. 范式 P3 · 双脊汇流（Twin-Spine）

两条长竖脊并列在左右，经济拆成两列夹在中间，最右一列收采购与终局。

| 项 | 约定 |
|---|---|
| 列分配 | 红 1 / 绿 2-3 / 金 4 / 灰紫 5 |
| 根 | 3 个，但重心明显偏向左右两条长脊 |
| 特点 | 适合"先军后金"节奏；对称感最强 |
| 指纹 | `R=3`、`D=10`、`C=5`、`P ▸ = 3-4-4-4-5-5-3-3-2-2`、`F=70%`、`X=12%`、`J=1`、`K=2`、`W=5`、`B=2`、`Lmax=10` |
| 代价 | 底部两行只有 2 个节点，收口松散；支线跨列距离大，虚线容易横穿画面 |

## 6. 选择决策表

| 想要的效果 | 选 |
|---|---|
| 像官方大明的树那样"三入口 → 撑开 → 收一点" | **P1-a** |
| 任务总数不多（20 出头），不想硬凑 | **P1-b** |
| 三条线里有一条明显更长（比如经济 10 个） | **P1-c** |
| 只有两条主线 | **P1-d** |
| 三条线语义互不相干，只想一眼分色 | **P2** |
| 明确"军事优先、经济后置"的玩法 | **P3** |
| 不想新建任何任务、纯重排 | **P2**（`J=0`，无需终局） |

> 提方案时的最短表达：`P1-a｜R3 D9 F82% J1` —— 一个编号加四个数就够了。

## 7. 工具链用法

```powershell
# 0) 算任意布局的指纹（R D C P F X J K W B Lmax）
& "analysis\MSK_missions\fingerprint.ps1"

# 1) 改布局：编辑 plans.json 的 plans[].nodes[]（id/label/key/line/slot/pos/parent）
# 2) 出图：校验 slot/position 规则并生成 svg + index.html
& "analysis\MSK_missions\gen_svg.ps1"
#    末尾会打印 [VIOLATIONS] none / 越界清单

# 3) 落地：把布局表写进 missions/MSK_missions.txt（自动备份 .bak）
& "analysis\MSK_missions\rebuild_msk_missions.ps1" -DryRun   # 先干跑
& "analysis\MSK_missions\rebuild_msk_missions.ps1"           # 再落盘

# 4) 若有新增任务，同步 decode_localisation/*.yml 的 _title/_desc
```

`plans.json` 节点字段：

```json
{ "id": "C3", "slot": 1, "pos": 3, "label": "风纪委员的巡逻艇",
  "key": "1_3", "line": "conquest", "parent": ["C2"] }
```

- `line`：`conquest` / `economy` / `empire` / `aux` / `final`，决定配色与图例
- `parent`：填 `id` 数组，脚本据此画线并校验 R3/R4
- `ghost: true`：画成虚线灰框，表示"建议删除/合并"的待定节点
- `keyLabel`：覆盖左下角的 key 文本（合并多个 key 时用）

## 9. 已知坑

1. **`position` 与 `slot` 极易写反** —— 写反的树会塌成"某一列里的一根竖柱"，连线全消失。
2. **跨列依赖差一行就断** —— `Δ行 = 2` 的跨列箭头游戏里根本不画，但脚本不报错，只能靠本文件的校验脚本或进游戏看。
3. **不要用 `max_slots_horizontal`** —— wiki 提过，但 1.37.5 全盘 0 命中，属过时信息。
4. **空任务树不存在** —— 只写 `slot` 不写任务的容器无先例，删任务时要连带删容器或留至少一个任务。
5. **改 key 必须同步 loc** —— key 重编后 `localisation/` 里旧 key 不会自动失效，会残留死文本，必须整段替换。
6. **`custom_tooltip` 里的 loc key 不受任务 id 改名影响** —— 它引用的是字符串，改名会让 loc 与 effect 脱节，重排时默认不动它。
