01结论摘要

核心判断：母 mod 0.5 做的是一次兵种体系重构，不是普通内容更新。它新增 36 个兵种组 acgr_g01..g36，把「兵种组」从 technology_group 里独立出来，改用国家级 unit_type = acgr_gXX + set_country_flag 标记；technology_group 一律退回原版组（western 29 国 / muslim 7 国）。

我方 submod 是「整文件覆盖」型 —— 2222 个文件里 1319 个与母 mod 同名，覆盖即替换。母 mod 对这 1319 个文件的所有更新，在我方 submod 生效时全部失效。其中两处是「一进游戏就坏」级别：common/technology.txt（抹掉 36 组注册）与 common/technologies/mil.txt（抹掉 981 条 enable，含 855 条 acgr 兵种解锁）。

8 条要点

  • 硬伤 原版 14 个 unit_type 全部落在 technology.txt 组名集合内（0 例外）→ 兵种组必须先注册成科技组。我方 20 组的 technology.txt 会让母 mod 的 972 个 acgr 兵种 + 280 国的 unit_type 指向未注册组。
  • 硬伤 我方 mil.txt 883 条 enable、0 条 acgr；母 mod 1791 条、855 条 acgr。覆盖 = acgr 兵种永不向任何国家解锁。
  • 好消息 tech_gensokyan 与 western 在科技数值上完全等价（start_level 3 / cost 0）。它唯一作用是「72 个 gen_t* 兵种的归属」+「1870 省的视野锚点」—— 这是所有取舍的支点。
  • 好消息 母 mod 新版的历史日期条目没有一条被我方覆盖丢失（355 省全部 HistDelta ≥ 0），时间线不用抢救。
  • 量化 1270 交集省中 1,015 个只多一行 discovered_by（机械合并），255 个有实质差异，高风险 239 省：qng→qin 22、fra→jda 13、文化改名 5、hmc→lsw/shj 5、hts↔frr 3。母 mod 新版共改 835 个键值 token / 253 省。
  • 版图 母 mod 重做了版图：QNG(清)→QIN(秦)、FRA→JDA、HMC→SHJ、HTS→FRR，共 43 省。我方旧 owner 会让这些新国家变无地国。
  • 伙伴 PT 做的是一整套科技组体系迁移（284 国 technology_group → acgr、省份 42,905 行 acgr discovered_by、72 兵种 unit_type → acgr_g01），自洽但有 4 条代价，其中「抹平科技成本」与「幻想乡兵种一刀切」不可接受。
  • 可用 PT 唯一可直接吸收：common/technologies/mil.txt = 母 mod 2417 行 + 我方 74 条 enable，零丢失的干净合并产物。

03三个核心冲突的判定

冲突 1 · 科技组视野 —「每省都要定义」对一半

discovered_by = X 的匹配对象是国家的 technology_group（或国家 TAG 作历史发现者），不是 unit_type。原版省份取值集合 = 18 个原版组 + 大量国家 TAG，就是这个道理。

母 mod 的 36 个 acgr 组
只是兵种组，technology_group = acgr_ 全库命中 0 → 完全不需要 discovered_by（母 mod 自己一条都没写）
我方 tech_gensokyan
是真正的 technology_group → 必须逐省写，1870 条本身没错
PT 的做法
删 1870 条我方视野 + 加 42,905 行 acgr 视野 —— 只有在他「把 284 国 technology_group 改成 acgr」的前提下才自洽，属于换体系不是补漏洞
